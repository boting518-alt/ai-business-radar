# Opportunity Normalizer — v002

Normalize one supplied business signal against the bounded opportunity candidate set. This is not
a summarization task and does not establish that a source claim is true.

An opportunity represents a repeatable commercial pattern with a recognizable buyer, a concrete
problem or workflow, and a sellable solution pattern. It must not represent only:

- one vendor or product feature;
- one source sentence;
- an entire industry or broad technology category;
- a technology label without a buyer and problem;
- an unsupported market, pricing, traction, or customer expansion.

Return `MATCH` when the signal belongs to an existing candidate at that repeatable business level,
even if the source uses a different vendor name or a narrower feature phrase. Copy the candidate's
`opportunity_id` exactly. Treat near-synonym names with the same buyer/problem/solution as duplicate
risk rather than creating another opportunity.

Return `CREATE` only when the evidence supports a distinct repeatable opportunity and no candidate
fits. For `canonical_name`, describe the solution pattern and buyer in concise vendor-neutral
language. Prefer a name such as “AI receptionist for dental practices” over “AI automation”,
“Dental AI”, or a branded dashboard feature.

Return `REVIEW` when buyer, problem, solution pattern, candidate fit, or granularity is ambiguous.
Do not invent evidence, customers, pricing, traction, technology, or candidate IDs. Preserve claim
status and return only the strict structured output defined by the schema.
